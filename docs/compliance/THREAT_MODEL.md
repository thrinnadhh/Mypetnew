# Threat model

Status: STRIDE-informed source assessment, 2026-08-15. Severity considers confidentiality, integrity, availability, financial, safety and regulatory impact. `Implemented` means visible in source/tests, not proven in production.

| Threat / abuse case | Assets and boundary | Severity | Implemented prevention/detection | Residual risk and required action | Status |
|---|---|---:|---|---|---|
| OTP brute force, flooding, credential stuffing or code disclosure | Customer identity; public API → identity service/SMS | High | hashed challenge, salted verification value, mobile-hashed rate key, expiry, cooldown, attempt cap; codes excluded from logs | In-memory state resets/does not coordinate replicas; production SMS/provider fraud controls, distributed limiter, IP/device signals and safe support recovery absent | PARTIAL / DEPLOYMENT_BLOCKER |
| Refresh-token theft or replay | Mobile secret store → API → session DB | Critical | hashed refresh token, rotation, lineage replay revocation, short access lifetime, secure native storage, logout/account-deletion revocation | Device binding/anomaly detection, key-management evidence, forced global logout UI and physical extraction tests absent | PARTIAL |
| Customer IDOR on profile/rights/deletion | Customer app → API privacy resources | High | actor ID derived from authenticated principal; repository query requires customer and request ID; cross-user tests | Case-worker/admin endpoints and production integration tests do not exist | IMPLEMENTED for current customer surface |
| Cross-merchant/cross-outlet access | Merchant app → API → commerce/loyalty | Critical | role/org/outlet claims and source guards; negative contract tests | Broader production repository paths, compromised admin and claim lifecycle need tests; row-level DB defence-in-depth absent | PARTIAL |
| Captain accesses unassigned delivery/customer details | Captain app → delivery resources | High | Delivery/captain domain not implemented, so no current data flow | Feature must bind assignment server-side, expose minimum contact window and test assigned/unassigned/cross-captain cases before creation | NOT_APPLICABLE_WITH_REASON / FUTURE_GATE |
| Admin privilege escalation or session hijack | Admin web/IdP → privileged API | Critical | explicit admin role checks on current endpoints | No production IdP/MFA, privileged session hardening, approval workflow, device policy or comprehensive admin audit | BLOCKED |
| Direct client access to Supabase/domain tables | Untrusted app → database/storage | Critical | server-only JDBC boundary; no client domain SDK; private storage adapter contract | Deployed database grants/RLS, network allowlist, service-key scope and bucket policy inaccessible | PARTIAL / DEPLOYMENT_BLOCKER |
| SQL/command/injection and mass assignment | Untrusted input → API/database/providers | High | typed DTOs, enum/length validation, parameterised JDBC, no shell provider calls | Global request-size/schema policy and dynamic security tests limited; free-text rights data needs output encoding/redaction | PARTIAL |
| Mobile reverse engineering or embedded secrets | Distributed app binary | High | only public config expected; source scan rejects public privileged variables; protected token storage | Binary/static analysis, certificate pinning decision, root/jailbreak threat decision and signed production build evidence absent | PARTIAL |
| Malicious deep link/notification route | Provider/user content → app navigation | High | allowlisted routes and UUID resource IDs in shared contract; no arbitrary URL execution | Physical Android/iOS killed/background/foreground tests and server-to-client compatibility proof pending | PARTIAL |
| Sensitive lock-screen notification | Backend/provider → device screen | High | service rejects mobile/email, OTP, payment secret, prescription/diagnosis, exact-coordinate patterns; minimal route contract | Keyword policy is not a complete DLP engine; template allowlist/local preview review and physical screenshots needed | PARTIAL |
| FCM token leakage, stale delivery or takeover | DB/worker → Firebase → device | High | AES-GCM protected token, fingerprint only, owner-bound register/unregister, blank-on-revoke, invalid-token deactivation | KMS/rotation, Firebase roles/region, delete-account/logout zero-delivery physical evidence absent | PARTIAL |
| Exact location overcollection or tracking | Device → API/maps/logs | High | no location permission, field or provider currently; separate optional purpose defined | Future implementation requires foreground minimum precision, manual alternative, no background default, TTL, processor review and tests | NOT_APPLICABLE_WITH_REASON / FUTURE_GATE |
| Card/CVV/UPI PIN or bank password reaches MyPet | App/API/log/DB → payment provider | Critical | no integration or fields; CI blocks credential-shaped fields; hosted-provider design rule | Cashfree contract, hosted SDK/UI, signed webhook, raw payload/log tests and PCI/RBI review absent | BLOCKED until payment integration |
| Forged/replayed payment webhook | Public provider callback → order state | Critical | Endpoint absent | Require signature against raw body, freshness/replay store, idempotency, amount/currency/order binding, refund/reconciliation states and negative tests | FUTURE_BLOCKER |
| Malicious/oversized merchant document | Merchant/admin → private object storage | High | permission checks, private bucket intent, short signed access | MIME/magic/size/malware scanning, quarantine, deployed bucket policy, object-version lifecycle and signed-URL tests absent | BLOCKED |
| Consent dark pattern or stale notice | UI → consent ledger/downstream provider | High | independent opt-in toggles, default off, versioned proof, easy withdrawal | No immutable notice registry, multilingual legal text, downstream fan-out or UX accessibility/dark-pattern test | PARTIAL |
| Erased account reappears after restore | Backup → production DB | Critical | deletion tombstone and suppression window; direct erase transaction | No restore pipeline enforcing tombstones, provider backup window evidence or completed restore drill | BLOCKED |
| Sensitive data in logs, analytics, crash tools or tickets | All services → operators/processors | Critical | direct stdout logging prohibited by CI; source scans; notification content checks | No central logger/redactor, India-located sink, field-level allowlist, access monitoring or DLP scan of deployed telemetry | BLOCKED |
| Dependency, CI or secret compromise | Git/dependency registry/runner → build/release | Critical | wrapper validation, frozen lock, dependency review/audit, history-capable checkout, secret scan, least CI permission | Two expiring Metro/image parser exceptions; no SBOM/signing/provenance, branch-setting evidence or production deploy approvals | PARTIAL |
| Processor breach/cross-border disclosure | API → Supabase/Firebase/Expo/other | High | processor inventory and data minimisation design | Contracts, regions, subprocessor lists, transfer position, breach SLA and deletion proof mostly unknown | BLOCKED |
| Redis cache treated as authority or retains PII | API → future Redis | High | Redis absent and architecture rule says no business authority | Before adoption enforce TTL, encryption, auth, India region where required, backup exclusion and source-of-truth tests | NOT_APPLICABLE_WITH_REASON / FUTURE_GATE |
| Insider bulk export or support misuse | Admin/support/database → external | Critical | current admin features narrow, server role guards | No JIT access, dual approval, export controls, query anomaly alerts, staff training or audited break-glass evidence | BLOCKED |
| Denial of service / resource exhaustion | Internet/provider → API/DB/SMS | High | local limits and input caps on selected paths | WAF/global throttles, circuit breakers, autoscaling/load tests, SMS spend cap and recovery objectives absent | BLOCKED |

## Review triggers

Review this model before adding a processor, data field, role, location permission, analytics, payment/webhook, health/veterinary feature, document type, direct database client, Redis use or cross-border route; after any high incident; and at least quarterly. A Critical/High `BLOCKED` row requires explicit owner, fix and verified evidence before production—not a broad risk acceptance.
