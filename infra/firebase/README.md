# Firebase Sprint 1 boundary

Create separate Firebase projects for `development`, `staging`, and `production`. Register Customer, Merchant, and Captain as separate Android/iOS apps in each project, using the package and bundle identifiers generated by each Expo `app.config.ts`. A backend accepts device registrations only for its matching canonical environment.

The backend FCM HTTP v1 adapter uses Google application-default credentials with the `firebase.messaging` scope. Mount the service-account credential through the server secret manager and set `GOOGLE_APPLICATION_CREDENTIALS`; never commit the JSON, place it in an Expo/Next environment, or include it in an application bundle. `FIREBASE_PROJECT_ID` and `MYPET_ENVIRONMENT` select the permitted project/environment pair.

Native tokens are encrypted at rest with AES-256-GCM using the server-only `MYPET_DEVICE_TOKEN_KEY`. Rotate that key only with a reviewed re-encryption/re-registration plan. The JDBC worker claims attempts with bounded recovery, classifies invalid/transient/permanent FCM results, disables invalid registrations, and preserves a safe dead letter after the retry budget.

Before certification, exercise physical Android Customer/Merchant builds against the isolated project in foreground, background, and killed states; inject an FCM outage; verify replay/dedupe and allowlisted deep links; and retain redacted provider/outbox/inbox evidence. Expo Go and emulator-only delivery are not acceptable evidence. A distributed iOS candidate additionally requires APNs-through-FCM proof on a physical iPhone.
